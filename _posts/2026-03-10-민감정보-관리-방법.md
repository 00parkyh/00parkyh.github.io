# 🔐 민감정보(API Key, JWT 등) 관리 방법 정리

먼저 이 글을 작성하게 된 계기는 다음과 같습니다.

팀 프로젝트를 리팩토링하는 과정에서 시간 관계상 일부 **API Key, JWT Secret 등을 코드에 하드코딩하여 사용했던 부분**이 있었습니다.

이후 리팩토링을 진행하면서 **이러한 민감정보를 보다 안전하게 관리하는 방법이 무엇인지 찾아보게 되었고**, 관련 자료들을 정리하는 과정에서 이 글을 작성하게 되었습니다.

조사를 하던 중 **12-Factor App의 Config 원칙**을 참고하게 되었는데, 여기에서는 다음과 같은 내용을 권장하고 있습니다.

> 설정(config)은 코드에 저장하지 않고 환경 변수(environment variable)에서 관리하는 것이 좋다.
> 

참고 사이트

[https://12factor.net/ko/config](https://12factor.net/ko/config)

이를 바탕으로 **민감정보 관리 방법들을 정리해보았습니다.**

---

# 1️⃣ 코드 / properties 파일에 평문 하드코딩

### 방식

```
openai.api.key=sk-xxxx
```

### 장점

- 설정이 매우 간단함
- 별도의 설정 없이 바로 실행 가능

### 단점

- Git 저장소에 키가 포함될 가능성이 있음
- 협업 과정에서 여러 개발자가 키를 확인할 수 있음
- 키 변경 시 코드 수정 및 재배포가 필요할 수 있음

### 정리

가장 단순한 방식이지만 **민감정보가 코드 저장소에 포함될 수 있기 때문에 일반적으로 권장되지 않는 방식**입니다.

---

# 2️⃣ 환경변수(Environment Variable) 사용

### 방식

```
openai.api.key=${OPENAI_API_KEY}
```

환경 변수 설정

```
export OPENAI_API_KEY=sk-xxxx
```

### 장점

- 코드와 민감정보를 분리할 수 있음
- Git 저장소에 키가 포함되지 않음
- 키 변경 시 코드 수정 없이 환경 설정만 변경하면 됨
- Docker, CI/CD 환경에서도 활용하기 쉬움
- Spring Boot에서 기본적으로 지원하는 방식

### 단점

- 서버 접근 권한이 넓을 경우 환경변수 노출 가능성
- 로그 출력 등에서 실수로 노출될 가능성
- 서버 환경별로 환경변수 관리가 필요

### 정리

공식 문서나 여러 자료에서 **민감정보를 관리하는 일반적인 방법으로 환경변수 사용을 많이 권장하고 있습니다.**

---

# 3️⃣ `.env` 파일 사용

### 방식

`.env`

```
OPENAI_API_KEY=sk-xxxx
DB_PASSWORD=xxxx
```

### 장점

- 로컬 개발 환경에서 관리하기 편함
- 개발자별로 다른 환경 설정 관리 가능
- 환경변수 방식과 동일한 구조로 사용할 수 있음

### 단점

- 파일 형태이기 때문에 유출 가능성 존재
- `.gitignore` 설정을 하지 않으면 Git에 포함될 수 있음
- 운영 환경에서는 별도의 보안 관리가 필요

### 정리

`.env` 파일 방식은 **로컬 개발 환경에서 자주 사용되는 방법**이며, Git 저장소에 포함되지 않도록 관리하는 것이 중요합니다.

---

# 4️⃣ Secret Manager / Vault 기반 관리

### 예시 서비스

- AWS Secrets Manager
- HashiCorp Vault
- Naver Cloud Secret Manager
- GCP Secret Manager
- Azure Key Vault

### 방식

애플리케이션이 실행될 때 외부의 **비밀 관리 시스템(Secret Manager)**에서 값을 가져오는 방식입니다.

### 장점

- 중앙에서 민감정보 관리 가능
- 접근 권한 제어 가능
- 감사 로그 및 버전 관리 지원
- 키 자동 교체(rotation) 기능 지원

### 단점

- 초기 설정이 비교적 복잡함
- 별도의 인프라 설정이 필요함

### 정리

클라우드 환경에서는 **Secret Manager와 같은 중앙 비밀 관리 시스템을 사용하는 방법도 많이 사용되고 있습니다.**

---

# 📊 방식 비교 정리

| 방식 | 특징 |
| --- | --- |
| 평문 하드코딩 | 구현은 간단하지만 민감정보 노출 위험 존재 |
| 환경변수 | 코드와 민감정보를 분리할 수 있어 일반적으로 많이 사용 |
| `.env` 파일 | 로컬 개발 환경에서 사용하기 편리 |
| Secret Manager | 운영 환경에서 중앙 관리 가능 |

# 📌 정리

이번에 관련 자료들을 찾아보면서 느낀 점은

**민감정보를 단순히 숨기는 것보다 코드와 분리하여 관리하는 것이 중요하다는 점이었습니다.**

특히 **12-Factor App의 Config 원칙**에서도 설정 값은 코드가 아닌 **환경 변수(environment variable)**에서 관리하는 것을 권장하고 있습니다.

여러 방법들을 찾아보던 중, 현재 제가 진행하고 있는 프로젝트가 **Docker 환경에서 개발되고 있기 때문에 `.env` 파일을 활용하여 환경변수를 관리하는 방식이 비교적 적용하기 적합하다고 판단했습니다.**

```
개발 환경
.env + 환경변수

운영 환경
환경변수 또는 Secret Manager
```

앞으로 프로젝트를 진행할 때도 **API Key, JWT Secret, DB 비밀번호와 같은 민감정보는 코드에 직접 작성하기보다는 환경 설정을 통해 관리하는 방식으로 적용해볼 계획입니다.**

---

# ⚙ Spring Boot에서 `.env` 파일을 활용한 적용 예시

위에서 정리한 내용을 바탕으로 **Docker 환경에서 `.env` 파일을 활용하여 API Key를 관리하는 방법**을 간단히 정리해보았습니다.

## 1️⃣ `.env` 파일 생성

프로젝트 루트에 `.env` 파일을 생성하여 민감정보를 저장합니다.

`.env`

```
OPENAI_API_KEY=sk-xxxx
DB_PASSWORD=password
JWT_SECRET=jwt-secret-key
```

이 파일에는 **API Key, DB 비밀번호, JWT Secret 등 민감정보를 저장**할 수 있습니다.

또한 `.env` 파일이 Git 저장소에 포함되지 않도록 `.gitignore`에 추가해야 합니다.

`.gitignore`

```
.env
```

---

# 2️⃣ Docker Compose에서 환경변수 주입

Docker Compose에서는 `.env` 파일의 값을 **컨테이너 환경변수로 전달**할 수 있습니다.

`docker-compose.yml`

```
services:
  app:
    image: my-spring-app
    ports:
      -"8080:8080"
    environment:
      OPENAI_API_KEY: ${OPENAI_API_KEY}
      DB_PASSWORD: ${DB_PASSWORD}
      JWT_SECRET: ${JWT_SECRET}
```

이렇게 설정하면 `.env` 파일의 값이 **컨테이너의 환경변수로 전달**됩니다.

---

# 3️⃣ Spring Boot 설정

Spring Boot에서는 환경변수를 다음과 같이 사용할 수 있습니다.

`application.yml`

```
openai:
  api-key: ${OPENAI_API_KEY}

spring:
  datasource:
    password: ${DB_PASSWORD}

jwt:
  secret: ${JWT_SECRET}
```

---

# 4️⃣ Spring 코드에서 사용

Spring에서는 `@Value` 또는 `ConfigurationProperties`를 통해 값을 사용할 수 있습니다.

```
@Value("${jwt.secret}")
privateStringjwtSecret;
```

---

# 5️⃣ 적용 결과

이와 같은 구조로 설정하면 다음과 같은 장점이 있습니다.

- API Key, JWT Secret 등이 코드 저장소에 포함되지 않음
- `.env` 파일을 통해 환경별 설정을 쉽게 관리할 수 있음
- Docker 환경에서도 민감정보를 외부에서 주입할 수 있음
- 키 변경 시 코드 수정 없이 `.env` 값만 변경하면 됨
